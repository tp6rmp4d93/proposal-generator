# 服務建議書初稿產生器

上傳政府採購的招標文件（招標公告、招標規範／採購說明、投標須知、評選須知、契約草案、標價清單），設定版面字型後，一鍵產生一份**可直接以 Word 修改的服務建議書初稿（.docx）**。

所有文件都在瀏覽器內解析與排版，不會上傳到任何伺服器。

## 功能

**解析招標文件**：支援 `.odt`、`.docx`、`.pdf`、`.txt`。會自動判斷文件類型，擷取以下資訊：

- 計畫名稱、招標機關、預算金額、履約期限
- 工作項目與子項（對應第貳章各節與甘特圖）
- 分段進度／查核點、成果交付項目
- 評選項目與配分、評選須知「內容要領」
- 文中引用的法規與前期計畫（列入參考文獻）

解析結果都可以在介面上修改。

**LOGO 與頁首頁尾**：可上傳機關 LOGO 與投標廠商 LOGO（PNG、JPG、SVG、WebP 皆可，會自動轉為 PNG）。

- 頁首：左側為機關 LOGO＋標案名稱（自動取自招標文件），右側為該頁所屬的章節名稱（只到第一層，如「目錄」「第壹章　前言」「參考文獻」），下方為主題色線條。
- 頁尾：左側為投標廠商 LOGO，中間為頁碼，右側為廠商名稱（未上傳 LOGO 時名稱置左）。
- 封面：機關 LOGO 放在機關名稱上方，廠商 LOGO 放在投標廠商名稱上方。
- 目錄、表目錄、圖目錄每頁上方都有「機關／標案名稱／服務建議書」抬頭。
- 頁首文字與線條顏色可自訂，預設綠色 #2E7D32。
- 投標廠商名稱與 LOGO 會記在這台電腦的瀏覽器中，下次開啟自動帶入。

**版面字型設定**：標題 1～3、內文、圖表標題、表格文字分別設定中文字型、英文字型、字級、粗體、行距（單行、1.5 倍、2 倍、多倍、最小、固定行高）、段前段後、首行縮排與對齊方式。另可設定頁邊界、頁首、頁尾、頁碼與主題色，右側 A4 預覽即時更新。設定儲存在瀏覽器，下次開啟會自動載入。

**產生的 Word 檔包含**：

| 部分 | 內容 |
| --- | --- |
| 封面 | 機關、計畫名稱、投標廠商、民國年月 |
| 目錄 | 目錄、表目錄、圖目錄（Word 欄位，開檔時更新頁碼） |
| 第壹章 前言 | 計畫緣起與目的、委託工作範圍、工作架構圖、工作項目與章節對照表、評選項目與章節對照表、承攬優勢 |
| 第貳章 專案執行規劃 | 對計畫之瞭解、課題與對策、整體執行流程圖、各工作項目一節（子項為第三層標題）、創新性及可行性、建議 |
| 第參章 預期成果與效益 | 預期成果表、成果提送表、效益及附加價值 |
| 第肆章 專案品質及進度控管 | 甘特圖（依月份、含查核點 ★ 與累計進度）、查核點表、PDCA 品管圖、風險管理、資安及個資保護 |
| 第伍章 專案管理及履約能力 | 組織架構圖、分工表、人員學經歷表、執行中案件表、如期履約說明 |
| 第陸章 廠商規模與實績 | 廠商基本資料、相關實績表、主持人經驗 |
| 第柒章 企業社會責任 (CSR) | 員工薪資、工作與生活平衡、綠色採購 |
| 第捌章 標價清單及費用分析 | 標價清單（含中文大寫總價）、服務費用分析表 |
| 參考文獻、附錄 | 依類別編號；附錄預留證明文件位置 |

- 每一章（含目錄頁、參考文獻、附錄）是一個獨立的 Word 節，所以頁首右側的章名會自動對應；修改章名時，請一併修改該節頁首的文字。
- 圖表依章編號（如「表 2-1」「圖 4-3」），並套用「表標題」「圖標題」樣式，所以表目錄、圖目錄會自動帶出。
- 流程圖、組織圖、甘特圖都以 Word 表格繪製，可直接修改文字、增刪格子與網底。
- 需要補充的位置以黃色醒目的【待補：…】標示。

**AI 撰寫（選用）**：以 Claude Artifact 方式開啟時，可讓 Claude 依招標文件撰寫各章內文、課題對策表、各工作項目的作業流程圖、甘特圖排程與查核時間。費用由使用者自己的 Claude 額度支付。未涉及的事實（人名、實績、金額）一律以【待補】標示，不會捏造。在 GitHub Pages 或本機開啟時，沒有 AI 功能，會產生完整架構並以【待補】預留內文。

## 使用方式

1. 開啟網頁（GitHub Pages、本機或 Claude Artifact）。
2. 上傳招標文件。舊版 `.doc` 請先以 Word 另存為 `.docx` 或 `.odt`。
3. 檢查「確認解析內容」，補上投標廠商名稱，上傳機關與廠商 LOGO，視需要修改工作項目標題。
4. 設定版面字型，按「儲存排版設定」。
5. 勾選「我已確認解析內容與排版設定」，按「開始」。
6. 下載 Word 檔。開啟時 Word 會詢問是否更新欄位，請按「是」，目錄即會帶出頁碼。之後用尋找功能搜尋「【待補」逐一補充。

## 部署到 GitHub Pages

1. 將此專案推送到 GitHub。
2. 在儲存庫的 **Settings → Pages → Build and deployment** 將 Source 設為 **GitHub Actions**。
3. 推送到 `main` 分支後，`.github/workflows/pages.yml` 會執行測試、建置並發布。網址為 `https://<帳號>.github.io/<儲存庫名稱>/`；單一檔案版本位於 `/dist/proposal-generator.html`。

本機直接以瀏覽器開啟 `index.html` 即可使用（需連網以載入 CDN 函式庫）；或執行 `npm run serve` 後開啟 <http://localhost:8080>。

## 開發

```bash
npm install      # 安裝測試用的 docx 與 jszip
npm test         # 執行單元測試（解析與 Word 產生）
npm run build    # 產生單一檔案版本 dist/proposal-generator.html
```

### 專案結構

```
index.html               介面與樣式，載入 src/ 下的三支程式
src/parse.js             招標文件解析：ODT／DOCX／純文字擷取、文件分類、資訊擷取
src/gen.js               Word 產生器：章節、表格、流程圖、甘特圖、目錄、樣式
src/app.js               介面流程、排版設定、AI 撰寫、下載
scripts/build.mjs        將三支程式內嵌成單一 HTML
test/                    單元測試與測試用文件
```

### 常見的客製化

- **章節架構與固定文字**：`src/gen.js` 的「內容」區段，依序呼叫 `H1`／`H2`／`H3` 建立章節，`addTable`、`addFigure` 建立表格與圖。
- **預設字型、版面與頁首顏色**：`src/app.js` 的 `DEFAULT_LAYOUT`。
- **頁首、頁尾與封面 LOGO 的排版**：`src/gen.js` 的 `header()`、`footer()` 與 `cover`。
- **AI 撰寫的提示詞**：`src/app.js` 的 `RULES` 與 `draft()`。
- **解析規則**（例如新的章節名稱關鍵字）：`src/parse.js` 的 `analyze()`。

### 相依的外部函式庫（皆由 CDN 載入，版本已固定）

- [docx 9.5.1](https://github.com/dolanmiu/docx)：產生 .docx
- [JSZip 3.10.1](https://github.com/Stuk/jszip)：讀取 ODT／DOCX
- [PDF.js 3.11.174](https://github.com/mozilla/pdf.js)：讀取 PDF（上傳 PDF 時才載入）

## 限制

- 掃描影像的 PDF 沒有文字層，無法解析，請改用 ODT／DOCX 或先做 OCR。
- 解析規則依臺灣政府採購文件的常見格式（一、（一）、1.、(1) 編號或清單層級）設計；格式差異大的文件請在介面上手動修正，或使用「用 AI 重新解析」。
- 字型名稱會原樣寫入 Word；開啟檔案的電腦需安裝該字型才會正確顯示。
- 產出為初稿，送件前請務必依招標文件逐項檢核內容與格式。
